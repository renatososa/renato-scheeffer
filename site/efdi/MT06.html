Módulo Técnico 6: networking

En este módulo trabajamos sobre distintas estrategias de comunicación entre dispositivos, abordando tanto mecanismos cableados como Serial y SPI, como alternativas inalámbricas como BLE y WiFi utilizando el protocolo MQTT. La idea general fue entender cómo desacoplar tareas entre distintos nodos y permitir que cada dispositivo resuelva una parte del sistema intercambiando únicamente la información necesaria.

La tarea de este módulo consistió en comunicar dos ESP32. El ESP32 A fue definido como nodo sensor y se encargó de medir distancia con un HC-SR04, evaluar si una puerta debía abrirse o cerrarse a partir de un umbral y permitir además la conmutación manual mediante un pulsador. Ese nodo publica en un tópico MQTT el estado actual de la puerta. Por otro lado, el ESP32 B fue implementado como nodo actuador: se suscribe al mismo tópico, interpreta el estado deseado, enciende un LED verde o un LED rojo según si la puerta está abierta o cerrada y mueve un servomotor que representa el mecanismo de apertura y cierre.

Implementación del nodo sensor

El nodo sensor fue el encargado de decidir cuándo la puerta debía abrirse o cerrarse. Para ello se utilizaron dos criterios: la distancia medida por el HC-SR04 y el estado de un pulsador que permite alternar manualmente la condición de apertura. Si cualquiera de estos dos mecanismos indica apertura, el nodo publica el mensaje ABIERTO; en caso contrario publica CERRADO.

Configuración de WiFi y MQTT
#include <WiFi.h>
#include <PubSubClient.h>

const char* WIFI_SSID = "Wokwi-GUEST";
const char* WIFI_PASSWORD = "";

const char* MQTT_SERVER = "broker.hivemq.com";
const uint16_t MQTT_PORT = 1883;
const char* MQTT_TOPIC = "EFDI/networking";

WiFiClient wifiClient;
PubSubClient mqttClient(wifiClient);

void connectWiFi() {
  if (WiFi.status() == WL_CONNECTED) {
    return;
  }

  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);

  Serial.print("Conectando WiFi");
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println();
  Serial.print("WiFi conectado. IP: ");
  Serial.println(WiFi.localIP());
}

void connectMQTT() {
  while (!mqttClient.connected()) {
    String clientId = "ESP32_SENSOR_";
    clientId += String((uint32_t)(ESP.getEfuseMac() & 0xFFFFFFFF), HEX);

    Serial.print("Conectando a MQTT...");
    if (mqttClient.connect(clientId.c_str())) {
      Serial.println(" conectado");
    } else {
      Serial.print(" fallo, rc=");
      Serial.print(mqttClient.state());
      Serial.println(". Reintentando en 2 s");
      delay(2000);
    }
  }
}

En este primer bloque se incorporan las librerías necesarias para conectividad y se definen el SSID, la dirección del broker, el puerto y el tópico a utilizar. Luego se implementan dos funciones: connectWiFi(), que conecta el ESP32 a la red inalámbrica, y connectMQTT(), que establece la conexión con el broker MQTT. Para identificar al nodo dentro del broker se genera un clientId único a partir de la dirección del chip.

Sensado de distancia y lectura del pulsador
#define TRIG_PIN 5
#define ECHO_PIN 18
#define BOTON_PIN 19

#define REBOTE_BOTON_MS 60
#define ECHO_TIMEOUT_US 30000
#define OPEN_DISTANCE_THRESHOLD_CM 15.0f

bool estadoBotonEstable = HIGH;
bool ultimaLecturaBoton = HIGH;
unsigned long ultimoTiempoRebote = 0;
bool puertaAbiertaPorBoton = false;

float readDistanceCm() {
  digitalWrite(TRIG_PIN, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG_PIN, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG_PIN, LOW);

  unsigned long duracion = pulseIn(ECHO_PIN, HIGH, ECHO_TIMEOUT_US);
  if (duracion == 0) {
    return -1.0f;
  }

  return duracion * 0.0343f * 0.5f;
}

void manejarBoton() {
  bool lectura = digitalRead(BOTON_PIN);

  if (lectura != ultimaLecturaBoton) {
    ultimoTiempoRebote = millis();
    ultimaLecturaBoton = lectura;
  }

  if ((millis() - ultimoTiempoRebote) > REBOTE_BOTON_MS && lectura != estadoBotonEstable) {
    estadoBotonEstable = lectura;

    if (estadoBotonEstable == LOW) {
      puertaAbiertaPorBoton = !puertaAbiertaPorBoton;
    }
  }
}

Aquí se definen los pines del sensor ultrasónico y del pulsador, junto con el tiempo de rebote y el umbral de apertura fijado en 15 cm. La función readDistanceCm() genera el pulso de disparo del HC-SR04, mide el tiempo del eco y lo convierte a centímetros. Por otro lado, manejarBoton() implementa una lógica de antirrebote para que cada pulsación cambie de forma estable el estado manual de la puerta.

Lógica de decisión y publicación del estado
#define PUBLISH_INTERVAL_MS 250

unsigned long ultimoTiempoPublicacion = 0;
bool lastPublishedPuertaAbierta = false;

bool debePublicar(bool puertaAbierta) {
  if (millis() - ultimoTiempoPublicacion >= PUBLISH_INTERVAL_MS) {
    return true;
  }

  if (puertaAbierta != lastPublishedPuertaAbierta) {
    return true;
  }

  return false;
}

void publicarEstado() {
  float distanciaCm = readDistanceCm();
  bool puertaAbiertaPorDistancia = distanciaCm > 0.0f &&
                                   distanciaCm <= OPEN_DISTANCE_THRESHOLD_CM;
  bool puertaAbierta = puertaAbiertaPorDistancia || puertaAbiertaPorBoton;

  if (!debePublicar(puertaAbierta)) {
    return;
  }

  const char* payload = puertaAbierta ? "ABIERTO" : "CERRADO";

  bool ok = mqttClient.publish(MQTT_TOPIC, payload, true);
  if (ok) {
    ultimoTiempoPublicacion = millis();
    lastPublishedPuertaAbierta = puertaAbierta;
  }
}

En este bloque se concentra la lógica principal del nodo sensor. Primero se determina si la puerta debe abrirse por proximidad o por pulsación manual. Luego se construye el mensaje a publicar en el tópico MQTT. La función debePublicar() evita enviar mensajes innecesarios en cada ciclo del programa, permitiendo publicar únicamente cuando cambió el estado de la puerta o cuando pasó un intervalo máximo de tiempo sin actualizar.

Inicialización y rutina principal
void setup() {
  Serial.begin(115200);

  pinMode(TRIG_PIN, OUTPUT);
  pinMode(ECHO_PIN, INPUT);
  pinMode(BOTON_PIN, INPUT_PULLUP);

  connectWiFi();
  mqttClient.setServer(MQTT_SERVER, MQTT_PORT);
}

void loop() {
  if (WiFi.status() != WL_CONNECTED) {
    connectWiFi();
  }

  if (!mqttClient.connected()) {
    connectMQTT();
  }

  mqttClient.loop();
  manejarBoton();
  publicarEstado();
}

Finalmente, en setup() se inicializan el puerto serial, los pines y la configuración básica del cliente MQTT. En el loop() se supervisa permanentemente el estado de la conexión WiFi y MQTT, se actualiza la lectura del pulsador y se publica el estado de la puerta cuando corresponde.

Implementación del nodo actuador

El nodo actuador fue diseñado para recibir el estado publicado por el nodo sensor y traducir esa información en una acción física. Para ello se suscribe al tópico EFDI/networking, interpreta los mensajes recibidos y en función de su contenido mueve el servomotor y actualiza la señalización luminosa con dos LEDs.

Configuración de WiFi y suscripción MQTT
#include <WiFi.h>
#include <PubSubClient.h>
#include <ESP32Servo.h>

const char* WIFI_SSID = "Wokwi-GUEST";
const char* WIFI_PASSWORD = "";

const char* MQTT_SERVER = "broker.hivemq.com";
const uint16_t MQTT_PORT = 1883;
const char* MQTT_TOPIC = "EFDI/networking";

WiFiClient wifiClient;
PubSubClient mqttClient(wifiClient);
Servo barrierServo;

void connectWiFi() {
  if (WiFi.status() == WL_CONNECTED) {
    return;
  }

  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);

  Serial.print("Conectando WiFi");
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println();
  Serial.print("WiFi conectado. IP: ");
  Serial.println(WiFi.localIP());
}

void connectMQTT() {
  while (!mqttClient.connected()) {
    String clientId = "ESP32_ACTUATOR_";
    clientId += String((uint32_t)(ESP.getEfuseMac() & 0xFFFFFFFF), HEX);

    Serial.print("Conectando a MQTT...");
    if (mqttClient.connect(clientId.c_str())) {
      Serial.println(" conectado");
      mqttClient.subscribe(MQTT_TOPIC);
    } else {
      Serial.print(" fallo, rc=");
      Serial.print(mqttClient.state());
      Serial.println(". Reintentando en 2 s");
      delay(2000);
    }
  }
}

El nodo actuador utiliza la misma infraestructura de red que el nodo sensor, pero en este caso el objetivo es suscribirse al tópico en lugar de publicar. Por eso, dentro de connectMQTT() además de establecer la conexión con el broker se ejecuta mqttClient.subscribe(MQTT_TOPIC), habilitando la recepción de mensajes.

Interpretación de mensajes recibidos
bool puertaAbierta = false;
unsigned long ultimoTiempoMensaje = 0;

bool parsePayload(const char* payload, bool& abrirPuerta) {
  if (strcmp(payload, "ABIERTO") == 0) {
    abrirPuerta = true;
    return true;
  }

  if (strcmp(payload, "CERRADO") == 0) {
    abrirPuerta = false;
    return true;
  }

  return false;
}

void mqttCallback(char* topic, byte* payload, unsigned int length) {
  char message[80];

  if (length >= sizeof(message)) {
    length = sizeof(message) - 1;
  }

  memcpy(message, payload, length);
  message[length] = '\0';

  bool nuevoEstadoPuerta = false;

  if (!parsePayload(message, nuevoEstadoPuerta)) {
    Serial.print("Payload invalido recibido en ");
    Serial.print(topic);
    Serial.print(": ");
    Serial.println(message);
    return;
  }

  puertaAbierta = nuevoEstadoPuerta;
  ultimoTiempoMensaje = millis();
}

Este bloque se encarga de interpretar el contenido de cada mensaje recibido. La función parsePayload() verifica si el texto recibido es ABIERTO o CERRADO y lo transforma en una variable booleana. Luego, el callback MQTT copia el mensaje recibido, valida su contenido y actualiza el estado de la puerta.

Control del servomotor y de los LEDs
#define SERVO_PIN 18
#define LED_OPEN_PIN 4
#define LED_CLOSED_PIN 5

#define SERVO_OPEN_ANGLE 90
#define SERVO_CLOSED_ANGLE 0
#define MESSAGE_TIMEOUT_MS 2000

void writePinIfValid(int pin, bool estado) {
  if (pin >= 0) {
    digitalWrite(pin, estado ? HIGH : LOW);
  }
}

void aplicarSalidas() {
  bool mensajeActivo = ultimoTiempoMensaje > 0 && (millis() - ultimoTiempoMensaje) <= MESSAGE_TIMEOUT_MS;
  bool puertaAbiertaEfectiva = mensajeActivo && puertaAbierta;

  barrierServo.write(puertaAbiertaEfectiva ? SERVO_OPEN_ANGLE : SERVO_CLOSED_ANGLE);
  writePinIfValid(LED_OPEN_PIN, puertaAbiertaEfectiva);
  writePinIfValid(LED_CLOSED_PIN, !puertaAbiertaEfectiva);
}

Una vez que el mensaje fue interpretado, la función aplicarSalidas() transforma esa información en acciones concretas. Si el último mensaje recibido sigue siendo reciente, el sistema considera válido su contenido y posiciona el servomotor en 90° para abrir o en 0° para cerrar. Al mismo tiempo enciende el LED verde cuando la puerta está abierta y el LED rojo cuando está cerrada.

Inicialización y rutina principal
void setup() {
  Serial.begin(115200);

  pinMode(LED_OPEN_PIN, OUTPUT);
  pinMode(LED_CLOSED_PIN, OUTPUT);

  barrierServo.setPeriodHertz(50);
  barrierServo.attach(SERVO_PIN, 500, 2400);
  barrierServo.write(SERVO_CLOSED_ANGLE);

  connectWiFi();

  mqttClient.setServer(MQTT_SERVER, MQTT_PORT);
  mqttClient.setCallback(mqttCallback);

  aplicarSalidas();
}

void loop() {
  if (WiFi.status() != WL_CONNECTED) {
    connectWiFi();
  }

  if (!mqttClient.connected()) {
    connectMQTT();
  }

  mqttClient.loop();
  aplicarSalidas();
}

En setup() se inicializan los pines de salida, se configura el servomotor y se registra el callback que se ejecutará cada vez que llegue un mensaje del broker. Luego, en el loop(), se mantiene viva la conexión MQTT y se actualizan permanentemente las salidas para reflejar el último estado recibido.

Demostración del sistema real

Una vez validado el comportamiento general del sistema en simulación se realizó la implementación sobre hardware real, manteniendo la misma lógica de comunicación entre el nodo sensor y el nodo actuador mediante MQTT. Esta etapa permitió comprobar que la arquitectura propuesta efectivamente funcionaba fuera del entorno simulado y que el sistema podía resolver tanto el sensado como la actuación en una configuración física concreta. Para ello también fue necesario ajustar la configuración de red, reemplazando el SSID utilizado en la simulación de Wokwi-GUEST por la red local de mi casa, que fue la empleada durante las pruebas reales de comunicación.

Durante estas pruebas apareció una dificultad que no se había manifestado de forma clara en la simulación. A medida que el objeto se acercaba al campo de medición del HC-SR04, la lectura de distancia comenzaba a ajustarse de forma inestable, generando oscilaciones cerca del umbral y provocando aperturas o cierres erróneos. Para corregir este comportamiento fue necesario modificar el código del nodo sensor incorporando un filtrado simple sobre las mediciones consecutivas, de modo de suavizar la lectura antes de tomar la decisión de apertura. Esta corrección permitió lograr una respuesta más estable en la implementación real sin alterar la estructura general del sistema.

Conclusiones

Esta práctica permitió implementar una arquitectura simple pero muy representativa de un sistema distribuido, donde un nodo se encarga del sensado y de la toma de decisión, mientras que otro resuelve la actuación física a partir de los mensajes intercambiados. El uso de MQTT resultó especialmente útil para desacoplar ambas tareas y mantener la comunicación entre dispositivos de forma clara y escalable.

Además, la dificultad encontrada al intentar simular el sistema completo en la versión web de Wokwi llevó a explorar una alternativa más robusta dentro de Visual Studio Code. Esa transición no solo permitió completar la simulación correctamente, sino también entender mejor cómo preparar un entorno de trabajo más flexible para proyectos con varios nodos que comparten servicios de red.

Los códigos correspondientes a estas implementaciones se pueden encontrar en los enlaces del repositorio: por un lado el sketch del nodo sensor en sensor.ino y por otro el del nodo actuador en actuador.ino.
